# Constructor-theoretic benchmark for non-trajectory direction

**Date:** 2026-11-11  
**Author:** Felipe Gianini Romero  
**Status:** foundational benchmark for directed non-temporal transformation semantics  
**Novelty status:** constructor theory is an established research programme; no project originality claim

## 1. Why constructor theory is relevant

The pregeometric direction programme is looking for a semantics of directed structure that does not begin by saying:

> this state occurs before that state.

Constructor theory is directly relevant because it proposes that fundamental laws be expressed through which physical transformations are possible or impossible, rather than primarily through initial conditions plus equations of motion.

A transformation task can be written schematically as

$$
\mathcal A=\{x\to y,\ldots\}.
$$

The statement that a task is possible is not itself a trajectory prediction.

This makes constructor theory an important anti-circularity benchmark.

## 2. What is gained

A constructor-theoretic task can express directional physical content without assigning:

- a timestamp to x;
- a duration to the task;
- a differential trajectory from x to y;
- a global background temporal coordinate in the task notation itself.

Thus it gives another legitimate answer to:

> What can a directed arrow mean if it does not mean temporal precedence?

It can mean:

> an input attribute can be transformed into an output attribute by an arbitrarily accurate constructor under the declared laws.

## 3. The polarity is still present

The task

$$
x\to y
$$

is not the same object as

$$
y\to x.
$$

The input/output distinction is part of the task specification.

Therefore constructor theory does not obtain polarity from an untyped symmetric pair

$$
\{x,y\}
$$

for free.

It assumes or defines a transformation type with source and target roles.

This is fully legitimate physics.

For the present project it means:

$$
\boxed{
\text{trajectory-free direction}
\neq
\text{polarity-free foundation}.
}
$$

## 4. Relationship to resource convertibility

Resource theory asks whether an allowed conversion exists:

$$
x\succeq y.
$$

Constructor theory retains the more explicit task-level question:

$$
x\to y
\quad\text{possible or impossible?}
$$

Passing from detailed conversion processes/tasks to a yes/no convertibility relation is analogous to a preorder reflection.

This matches the classical observation in resource-theory literature that a category of conversions contains more information than its convertibility preorder.

Thus:

$$
\boxed{
\text{tasks/processes}
\to
\text{convertibility preorder}
}
$$

is another controlled information-losing step.

## 5. Thermodynamic relevance

Constructor-theoretic thermodynamics uses possible/impossible tasks to formulate exact restrictions associated with work, heat, and irreversibility without relying only on macroscopic trajectories.

This is highly relevant to the repository because it shows that:

- irreversibility can be stated as a constraint on possible transformations;
- a transformation arrow need not be identified with an external clock reading;
- resource-like directed structure can be physically meaningful.

Again, none of this implies that the arrow itself has been derived from a symmetric substrate.

## 6. What constructor theory does not give this project for free

The present direction problem asks:

> What non-temporal physical fact chooses one polarity rather than its reverse?

Constructor theory can answer:

> the laws say one task is possible and the transpose task may be impossible.

But if the project asks **why the primitive task relation has that asymmetric possibility structure**, the answer depends on the constructor-theoretic laws or subsidiary physics.

Therefore the polarity has moved into the possible/impossible task structure.

It has not disappeared.

## 7. Anti-circularity assessment

### No explicit trajectory time required in task statement

**PASS.**

### Directed physical semantics without calling the arrow “precedence”

**PASS.**

### Polarity generated from an untyped symmetric substrate

**NOT PROVIDED AUTOMATICALLY.**

### Physical duration

**NOT PROVIDED BY THE BARE TASK ARROW.**

### Causal order

**NOT IDENTICAL TO GENERAL TASK convertibility.**

A task can concern information copying, work extraction, computation, or another transformation without representing a causal ordering of two spacetime events.

## 8. Implication for R

Constructor theory gives a second clean non-temporal interpretation of directed R:

$$
R(x,y)
=
\text{“the task }x\to y\text{ is possible under the declared theory.”}
$$

This is more process-rich than bare resource convertibility.

It demonstrates that directed R need not be temporally circular.

But the project must still distinguish:

- transformation polarity;
- causal precedence;
- temporal order;
- duration.

## 9. Input/output typing is substantive information

The source/target typing of a task should be treated as information.

It is not equivalent to an unordered pair with a decorative arrow.

If a primitive substrate is completely symmetric under exchange

$$
x\leftrightarrow y,
$$

then declaring only \(x\to y\) possible already breaks that symmetry.

The symmetry-orientation theorem therefore still applies at the deeper level:

> an asymmetric possible-task structure contains asymmetric physical information somewhere.

## 10. Possible research use

Constructor theory suggests a disciplined possible route for the repository:

1. define a genuinely non-temporal set of physical attributes;
2. define candidate transformation tasks between them;
3. state possible/impossible structure without interpreting the task arrow as time;
4. quotient to a convertibility preorder if useful;
5. test whether an accepted causal/clock structure can be recovered from the task algebra under additional conditions.

Step 5 is not supplied by constructor theory automatically.

It would be the actual bridge that the repository would need to prove.

## 11. Novelty boundary

The project must not claim novelty for:

- possible/impossible transformation language;
- task-based physical laws;
- resource convertibility;
- exact constructor-theoretic thermodynamic irreversibility;
- information-theoretic constructor principles.

These belong to established constructor/resource-theory research.

The only project-specific value at present is using this literature to sharpen the anti-circularity and polarity requirements.

## 12. Current conclusion

Constructor theory gives strong evidence that a physically meaningful arrow can be formulated without making it a clock coordinate.

At the same time it confirms the central obstruction:

$$
\boxed{
\text{polarity must exist somewhere in the physical structure}.
}
$$

Removing trajectories does not remove the source/target distinction.

The repository's unresolved problem therefore remains:

> Can a source/target or influence polarity itself be derived from a more symmetric non-temporal structure, or must it be primitive/sector-selected?

No answer is currently established.
